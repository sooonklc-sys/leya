# Лея

Веб-сервис для скрининга лабораторных данных. Исследовательский прототип по кейсу Сеченовского университета.

## 1. Цель и задачи решения

**Цель:** Разработать веб-сервис на основе методов машинного обучения для автоматизированного скрининга лабораторных данных с целью выявления анемии и латентных дефицитных состояний и определения их вероятного профиля.

**Задачи:**

1. Структурировать данные.
2. Проверить качество данных.
3. Определить признаки анемии.
4. Оценить возможные причины.
5. Оценить достаточность информации.
6. Представить результат.

## 2. Реализованные возможности

- Ручной ввод возраста, пола и 35 лабораторных показателей.
- Импорт текстового PDF лаборатории с проверкой значений пользователем перед переносом в форму.
- Проверка формата значений, обязательных полей, пропусков и ошибок преобразования чисел в даты Excel.
- Оценка признаков анемии по отдельному правилу уровня гемоглобина.
- Оценка возможного профиля дефицитов с помощью Random Forest. Предусмотрены модели для ОАК и расширенного набора исследований.
- Ограничение оценки причин при отсутствии необходимых показателей или выходе значений за диапазоны обучающей выборки.
- Формирование сводки для врача и редактируемой памятки пациенту с печатью и сохранением в PDF через браузер.
- Выполнение расчётов в браузере и автономная сборка приложения в один HTML-файл.

Код приложения находится в `dist/`, код обучения — в `training/`, тесты — в `tests/`, настройки — в `config/`. Архитектура описана в [документации](docs/ARCHITECTURE.md). Для демонстрации предусмотрены [синтетический набор](examples/demo.csv) и [презентация](docs/presentation/leya.pdf).

## 3. Развёртывание, запуск и использование

### 3.1. Требования к окружению и зависимости

| Вариант запуска | Требования |
|---|---|
| Из исходного кода | Node.js 20 или новее, современный браузер. Автоматические проверки используют Node.js 22 |
| В контейнере | Docker Engine или Docker Desktop с Compose v2, браузер |
| Готовый автономный HTML | Браузер. Проверка выполнена в Microsoft Edge |

Для запуска, тестирования и сборки приложения внешние npm-зависимости не требуются. Выполнять `npm install` не нужно. Библиотека JSZip и шрифты включены в репозиторий с лицензиями. Python и зависимости из `training/requirements.txt` нужны только для повторного обучения модели, а не для запуска сайта. Установка этих зависимостей описана в [инструкции](docs/DEPLOYMENT.md#повторное-обучение).

### 3.2. Запуск из исходного кода

Скачать репозиторий через **Code → Download ZIP**, распаковать и открыть терминал в папке с `package.json`. При использовании Git:

```sh
git clone https://github.com/sooonklc-sys/leya.git
cd leya
```

Запустить сервер:

```sh
npm start
```

Открыть [http://127.0.0.1:8765/](http://127.0.0.1:8765/). Адрес доступен только на компьютере, где запущен сервер. Остановка — `Ctrl+C`. Настройки по умолчанию находятся в `config/server.json`. Переменные `HOST` и `PORT` позволяют изменить адрес прослушивания и порт; примеры приведены в [инструкции развёртывания](docs/DEPLOYMENT.md).

### 3.3. Запуск в Docker

Из корня репозитория:

```sh
docker compose -f config/compose.yaml up --build -d
```

Открыть `http://127.0.0.1:8765/`. Для первоначального получения базового образа требуется интернет. Порт контейнера публикуется только на локальном интерфейсе компьютера.

Остановка:

```sh
docker compose -f config/compose.yaml down
```

### 3.4. Проверка и автономная сборка

```sh
npm test
npm run build
```

Сборка создаёт `release/hemonavigator.html`. Файл содержит приложение, модель и ресурсы, открывается в браузере без сервера и интернета. Техническое имя файла сохранено для совместимости.

Готовая сборка также доступна в GitHub Actions: успешный запуск «Проверка проекта», артефакт `hemonavigator-offline`. Для скачивания из закрытого репозитория необходим доступ. Порядок тестирования описан в [документации](docs/TESTING.md).

### 3.5. Размещение на хостинге

Разместить содержимое `dist/` в корневом каталоге статического сайта с сохранением вложенных путей. Главная страница — `index.html`. Серверный расчёт, база данных и API-ключи не требуются. Исходный датасет и реальные лабораторные файлы на хостинг не загружаются. Подробности приведены в [инструкции](docs/DEPLOYMENT.md#статический-хостинг).

### 3.6. Использование

1. Ввести показатели вручную, выбрать учебный пример или загрузить текстовый PDF. Для PDF сверить результаты и единицы, отметить проверку и нажать «Перенести в форму». Указать возраст и пол.
2. Проверить значения и единицы. Отсутствующие показатели оставить пустыми.
3. Нажать «Проанализировать» и изучить сводку и ограничения.
4. Подготовить объяснение пациенту, отредактировать текст и указать следующий шаг.
5. Проверить содержание памятки, поставить отметку проверки и открыть печать. При необходимости выбрать сохранение в PDF.

При изменении анализов прежняя памятка сбрасывается. После перезагрузки страницы введённые данные не сохраняются. Учётных записей, истории пациентов и автоматической отправки памяток в MVP нет.

## 4. Входные и выходные данные

### Входные данные

| Данные | Формат и требования |
|---|---|
| Возраст | `age_years`, целое число от 18 до 93 |
| Пол | `sex`, `F` или `M` |
| Гемоглобин | `hemoglobin`, `Hb` или `HGB`, г/л |
| Основные показатели для модели причин | RBC, гематокрит (HCT), MCV, MCH, MCHC, тромбоциты (PLT), WBC |
| Дополнительные показатели | RDW-CV, ретикулоциты, показатели обмена железа, витамины, маркеры воспаления и другие поля словаря; допускаются пропуски |
| Файл | Текстовый PDF до 5 МБ и 10 страниц. Поддерживается таблица со столбцами «Тест», «Результат», «Норма», «Ед. изм.», включая продолжение на следующей странице |

Возраст, пол и гемоглобин необходимы для оценки Hb. Для модели причин дополнительно необходимы перечисленные основные показатели. RDW-CV необязателен для расчёта и не заменяется RDW-SD.

Результаты PDF извлекаются по расположению столбцов. Неподдерживаемые единицы, неоднозначные числа и повторные показатели не подставляются автоматически. Сканы, фотографии, защищённые паролем и произвольные виды бланков не поддерживаются. Единицы автоматически не пересчитываются. Загрузка Excel/CSV из интерфейса удалена; табличные функции сохранены для разработческих тестов.

Перечень полей и единиц: [описание данных](docs/DATA.md), `dist/schema.json`. Синтетический набор для автоматических тестов: [demo.csv](examples/demo.csv). Диагностические метки и идентификаторы не используются как признаки модели. PDF.js 5.6.205 поставляется локально с лицензией Apache-2.0 в `dist/vendor/`; обращения к CDN не требуются.

### Выходные данные

- Оценка признаков анемии по уровню гемоглобина.
- Предположения о возможном профиле дефицитов в пределах применимости модели.
- Информация о пропусках, ограничениях и достаточности данных для расчёта.
- Сводка для врача с основаниями результата.
- Редактируемая памятка пациенту, доступная для печати или сохранения в PDF.

## 5. API

Публичный серверный API для передачи анализов и получения расчёта не реализован. Обработка файлов и вычисления выполняются в браузере. Локальный сервер раздаёт статические файлы приложения и не принимает лабораторные данные для анализа.

`variables.xlsx` является словарём переменных и единиц измерения, а не API. Внутренние функции приложения и необязательная экспериментальная интеграция WebMCP описаны в [документации интерфейсов](docs/INTERFACES.md).

## 6. Ограничения и особенности медицинской тематики

- Решение является исследовательским прототипом. Независимая клиническая валидация не выполнена; автоматический результат не является диагнозом или назначением лечения.
- Оценка достаточности информации относится к условиям работы модели и не подтверждает полноту обследования пациента. Результат требует проверки врачом с учётом клинических сведений.
- Пропущенный показатель остаётся неизвестным. Отсутствие исследования не означает норму или латентное дефицитное состояние.
- Баллы модели не откалиброваны и не являются вероятностями диагноза. Порог сигнала дефицита является техническим параметром.
- На внутреннем тесте из 210 записей accuracy для 12 классов составила 84,3% при расширенных анализах и 52,4% при ОАК. Это показатели классификации на одном источнике данных, а не подтверждение эффективности в клинической практике. Подробные выводы по одному ОАК ограничены.
- При отсутствии необходимых показателей ОАК или выходе за диапазоны обучающей выборки оценка причин не выполняется. Эти диапазоны не являются клиническими референсами.
- Дети и беременные вне заявленной области MVP. Возраст интерфейса ограничен 18–93 годами; качество для отдельных возрастных групп не подтверждено.
- Ошибки переноса значений, единиц и преобразования чисел в даты Excel требуют сверки с исходным бланком. Приложение не восстанавливает медицинские значения автоматически.
- Код приложения не отправляет анализы внешнему сервису и не сохраняет их в localStorage. Исходный датасет и реальные бланки не входят в репозиторий. Соответствие 152-ФЗ отдельно не подтверждено; локальный расчёт не заменяет оценку требований к обработке персональных данных.

Методика обучения и проверки: [карточка модели](docs/MODEL_CARD.md). Медицинские ограничения и обработка данных: [документация](docs/MEDICAL_AND_PRIVACY.md).
