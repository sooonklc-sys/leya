# Лея

**Помощник врача для разбора лабораторных анализов и подготовки понятной памятки пациенту.**

Исследовательский MVP по кейсу Сеченовского университета. Русскоязычный интерфейс, обработка CSV/XLSX в браузере и автономная версия для защиты без интернета.

[Презентация для жюри](docs/presentation/leya.pdf) · [Сценарий демонстрации](DEMO.md) · [Архитектура](docs/ARCHITECTURE.md) · [Соответствие требованиям](docs/REQUIREMENTS.md)

![Лея: разбор анализов на учебном примере](docs/screenshot.png)

## Цель и задачи

Помочь врачу разбирать лабораторные показатели при подозрении на анемию и дефицитные состояния. У разных пациентов доступен разный набор исследований. Сервис должен явно показывать пропуски и ограничения, отделять оценку гемоглобина от гипотез о причинах и помогать объяснить результат пациенту.

Задачи MVP: принять структурированные результаты, проверить ввод, выполнить локальную оценку, сформировать сводку врачу и редактируемое объяснение пациенту. Автоматические предположения не являются диагнозом. Независимой клинической валидации пока нет.

## Что реализовано

- Ручной ввод возраста, пола и 35 лабораторных показателей с названиями, аббревиатурами и единицами.
- Загрузка CSV/XLSX, выбор записи, сохранение пропусков и проверка ошибок Excel, включая даты вместо чисел.
- Отдельное правило оценки Hb и две версии Random Forest: для ОАК и расширенного набора исследований.
- Отчёт врачу: краткая сводка, гипотезы для проверки, состав данных и раскрываемое обоснование.
- Памятка пациенту: редактирование врачом, комментарий, следующий шаг, отметка проверки, печать или сохранение PDF.
- Автономная сборка в один HTML. Нет учётных записей, хранения истории и автоматической передачи памятки пациенту.

Основной сценарий: врач загружает анализы, проверяет сводку, редактирует памятку и передаёт её пациенту. Отметка проверки содержания не удостоверяет личность или квалификацию врача.

## Быстрый запуск

### Из исходного кода

Нужен **Node.js 20 или новее** и современный браузер. Проверки CI используют Node.js 22. Для запуска, тестов и сборки нет внешних npm-зависимостей: `npm install` не требуется. JSZip и шрифты уже включены с лицензиями.

Скачайте репозиторий через **Code → Download ZIP**, распакуйте его и откройте терминал в папке с `package.json`. Либо клонируйте репозиторий, если у вас есть доступ:

```sh
git clone https://github.com/sooonklc-sys/hemonavigator.git
cd hemonavigator
npm start
```

Откройте [http://127.0.0.1:8765/](http://127.0.0.1:8765/). Остановка: `Ctrl+C`. Этот адрес работает только на том компьютере, где запущен сервер. Для другого порта задайте `PORT`, как показано в [инструкции развёртывания](docs/DEPLOYMENT.md).

### Через Docker

Нужны Docker Engine или Docker Desktop с Compose. Из корня репозитория:

```sh
docker compose -f config/compose.yaml up --build -d
```

Откройте тот же локальный адрес. Остановка:

```sh
docker compose -f config/compose.yaml down
```

Первое получение базового образа требует интернета. Порт публикуется только на `127.0.0.1`. Docker не обязателен для демонстрации готового HTML. [Подробности и ограничения проверки](docs/DEPLOYMENT.md).

### Автономный файл для защиты

```sh
npm run build
```

Откройте `release/hemonavigator.html` двойным щелчком в Edge или Chrome. Внутри находятся сайт, модель, шрифты и иллюстрация. Интернет, Node.js и Docker на компьютере жюри для этого файла не нужны. Техническое имя файла сохранено для совместимости, название интерфейса — «Лея».

Также файл можно скачать из **Actions → успешный запуск «Проверка проекта» → Artifacts → hemonavigator-offline**. Доступ к артефактам закрытого репозитория требует входа в GitHub и прав доступа. До защиты проверьте автономный файл на оборудовании организатора.

## Как пользоваться

1. Выберите учебный пример или загрузите [демо-таблицу](examples/demo.csv). Все её строки вымышлены.
2. Сверьте загруженные цифры и единицы. Если показателя нет в бланке, оставьте поле пустым. RDW-CV необязателен, ретикулоциты находятся в дополнительном разделе.
3. Нажмите «Проанализировать». Изучите сводку и ограничения данных.
4. Нажмите «Подготовить объяснение пациенту», отредактируйте текст и укажите следующий шаг.
5. Проверьте содержание, поставьте отметку и откройте печать. Для PDF выберите «Сохранить как PDF» в окне браузера.

Изменение анализов сбрасывает прежнюю памятку. Перезагрузка страницы очищает введённые данные. [Демонстрация за три минуты](DEMO.md).

## Входные и выходные данные

| Вход | Требования |
|---|---|
| Возраст и пол | 18–93 года, `F` / `M` |
| Гемоглобин | `hemoglobin`, `Hb` или `HGB`, г/л |
| Для модели причин | Дополнительно RBC, HCT, MCV, MCH, MCHC, PLT, WBC |
| Остальные исследования | Необязательны, пропуск сохраняется как неизвестное значение |
| CSV / XLSX | До 5 МБ и 1000 записей, заголовки в первой строке, для XLSX первый лист без формул |

Выход: оценка Hb, гипотезы модели, перечень ограничений и редактируемая памятка. Баллы модели не являются вероятностью диагноза. PDF формируется через печать браузера.

Полный [контракт данных и единицы](docs/DATA.md), [программные интерфейсы](docs/INTERFACES.md). Серверного API расчёта нет: вычисления выполняются в браузере. `variables.xlsx` является словарём полей, а не сетевым API. PDF, фото анализов и XLS пока не распознаются.

## Структура репозитория

```text
dist/                     Исходники статического приложения и ресурсы
  app.js                  Форма, проверка ввода и взаимодействие
  import.js               Импорт CSV/XLSX и контроль дат Excel
  engine.js               Расчёт модели и ограничения применимости
  workflow.js             Сводка врачу и памятка пациенту
  localization.js         Названия, аббревиатуры и единицы
  model.json              Экспорт обученных моделей
  schema.json             Словарь полей и диапазоны обучающей выборки
config/                   Настройки сервера и Docker Compose
examples/                 Синтетическая демо-таблица и пояснения
tests/                    Автоматические проверки расчёта, импорта и сервера
training/                 Код и зависимости повторного обучения
docs/                     Архитектура, интерфейсы, модель, ограничения
  presentation/           Презентация PDF, редактируемые слайды и тезисы
.github/workflows/        Проверки, сборка HTML и проверка контейнера
Dockerfile                Образ приложения
serve.mjs                 Раздача статических файлов
build-offline.mjs         Автономная сборка
model-evaluation.json     Агрегированные метрики
```

`dist/` в этом проекте содержит сами исходники без транспиляции. Дублирующая папка `src/` не нужна. Настройки приложения находятся в `config/`; стандартные `package.json`, `Dockerfile` и `.github/workflows/` размещены там, где их ожидают инструменты.

## Проверки и качество модели

```sh
npm test
npm run build
```

Проверяются пороги Hb, пропуски, необязательный RDW, ограничения модели, CSV, признаки дат Excel и работа статического сервера. [Полный порядок проверки](docs/TESTING.md).

В датасете обучения 840 записей: 630 для обучения и 210 для отложенного теста.

| Модель | Accuracy, 12 классов | Macro-F1 |
|---|---:|---:|
| Расширенные анализы | 84,3% | 0,834 |
| Только ОАК | 52,4% | 0,438 |
| Расширенная модель с дополнительными пропусками | 66,2% | 0,609 |

Это внутренний тест на одном источнике до ограничений интерфейса, а не доказательство клинической эффективности. Из-за качества режима ОАК интерфейс ограничивает подробные выводы о причинах. [Методика, воспроизведение и ограничения](docs/MODEL_CARD.md).

## Медицинские ограничения и данные

Прототип не устанавливает диагноз, не исключает дефициты и не назначает лечение. Он не предназначен для детей и беременных. Диапазоны обучающей выборки не являются клиническими референсами. Отсутствие анализов не означает «латентную анемию» и не считается нормой.

Расчёты и импорт работают локально в браузере. Исходный датасет, реальные бланки и персональные данные не входят в репозиторий. Это техническая особенность MVP, а не подтверждение соответствия 152-ФЗ. [Границы медицинского применения и обработки данных](docs/MEDICAL_AND_PRIVACY.md).
