# Программные интерфейсы

Публичного HTTP API расчёта нет. `serve.mjs` принимает только GET/HEAD для статических ресурсов, другие методы возвращают 405. Загрузка PDF выполняется в браузере, запрос с анализами не отправляется серверу.

## Импорт PDF: `dist/pdf-import.js`

- `parseLabPDF(buffer, schema) → Promise<{measurements, warnings, ignored, pages}>`: ArrayBuffer PDF до 5 МБ и 10 страниц; локальный PDF.js 5.6.205. Ограничение чтения — 45 секунд. Сканы, пароль и повёрнутые страницы не поддерживаются.
- `parseLabPages(pages, schema)`: чистая функция для извлечённых текстовых элементов с нормированными координатами `{text,x,y,width,height}`. Ищет столбцы «Тест», «Результат», «Норма», «Ед. изм.», переносит их позиции на продолжение таблицы.
- `measurements`: массив `{key,value,unit,page}`. Значения — строки, единицы соответствуют форме; референсы не используются как результаты. Идентификаторы не включаются в возвращаемый объект.
- Неизвестная единица, неоднозначное число или несколько результатов одного показателя оставляют поле пустым с предупреждением. Неизвестные строки учитываются в `ignored`.
- `app.js` показывает редактируемую таблицу сверки. Перенос возможен после отметки проверки; правка значения снимает отметку. До переноса расчёт заблокирован. Перенос заменяет предыдущие показатели, возраст и пол вводятся отдельно.

В автономной сборке библиотека и worker загружаются из встроенных Blob URL. CDN, OCR и серверное распознавание не используются.

## Табличные утилиты: `dist/import.js`

Эти функции сохранены для тестов и работы разработчика с синтетическими данными. Загрузка CSV/XLSX из пользовательского интерфейса удалена. JSZip больше не загружается страницей автоматически.

- `parseCSV(text) → string[][]`: UTF-8/Windows-1251 декодируются вызывающей стороной. Разделитель определяется по первой строке. Парсер поддерживает кавычки и не преобразует текст в даты.
- `parseXLSX(buffer) → Promise<string[][]>`: первый лист, глобальный JSZip и DOMParser. Массив также содержит `dateCells` с адресами и индексами дат. Формулы и превышение лимитов отклоняются.
- `rowsToRecords(rows, schema) → {records, ignored, unknown}`: сопоставление заголовков и строк. Значения остаются строками, пустоты сохраняются. Даты в числовых полях отклоняются до заполнения формы, даты в посторонних столбцах не мешают импорту.
- `spreadsheetDateIssues(values, schema) → {key, message}[]`: эвристика для вероятных серийных номеров дат вне диапазонов модели. Не восстанавливает первоначальные значения.

Ошибки импорта оформляются через `Error` с русским сообщением. `app.js` показывает сообщение пользователю, не перенося нераспознанный PDF в форму.

## Расчёт: `dist/engine.js`

`calculateReport(values, schema, model)` принимает **уже проверенный** объект: `age_years` целое 18–93, `sex` равен `F`/`M`, показатели конечные числа или `null`. Валидатор формы проверяет формат, обязательные значения и допустимость нуля до вызова. Функция не является самостоятельным валидатором внешнего API.

```js
const values = {
  age_years: 35, sex: 'F', hemoglobin: 138,
  RBC: 4.6, hematocrit: 41.4, MCV: 90, MCH: 30,
  MCHC: 333, platelets: 250, WBC: 6.1, RDW: null
}; // Синтетический пример
const report = calculateReport(values, schema, model);
```

| Поле отчёта | Значение |
|---|---|
| `values` | Копия проверенных измерений |
| `anemia`, `threshold` | Результат отдельного правила Hb и его порог |
| `severe` | Технический флаг Hb < 80 г/л в текущем прототипе |
| `variant` | `cbc` или `extended`, в зависимости от наличия дополнительных показателей |
| `missingBasic`, `outside` | Пропуски обязательных полей и значения вне обучающего диапазона |
| `withheld` | Оценка причин остановлена |
| `ranking` | 12 групп с неоткалиброванными баллами, пусто при `withheld` |
| `deficits` | Шесть отдельных сигналов, известные и отсутствующие уточняющие показатели |
| `influential` | До пяти показателей по чувствительности к замене медианой |
| `contradiction` | Несогласованность ведущего класса с правилом Hb, только после классификации |

Медианы заполняют пропуски только для обхода деревьев. Сигнал не подтверждает заболевание, отсутствие сигнала не исключает его. Код `workflow.js` дополнительно ограничивает выводы для режима ОАК.

## Представление результата: `dist/workflow.js`

`doctorOverview(report, schema)` формирует сводку. `setupMemo(getReport, schema)` управляет черновиком, правками, отметкой проверки и печатью. Медицинское решение принимает врач. Изменение исходных данных сбрасывает черновик и отметку проверки.

## Необязательный WebMCP

Если браузер предоставляет `document.modelContext.registerTool`, приложение регистрирует `stage_lab_values({values})`. Инструмент принимает только известные поля, числа/null и `F`/`M`, заполняет форму и возвращает `{staged: true, analysisRun: false}`. Это экспериментальная интеграция браузера, а не REST API. Она не нужна для работы сайта и не проверена в нативной среде WebMCP.
