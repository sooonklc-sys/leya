# Запуск, сборка и размещение

[Все документы](README.md) · [О проекте](../README.md).

Все команды выполняются из корня репозитория с `package.json`.

## Node.js

Node.js 20+, рекомендуется версия 22, используемая CI. Для приложения зависимости npm отсутствуют, установка пакетов не требуется.

```sh
npm start
npm test
npm run build
```

Адрес: `http://127.0.0.1:8765/`. Сборка: `release/leya.html`. Остановка сервера: Ctrl+C.

Другой порт в PowerShell:

```powershell
$env:PORT = '8766'
npm start
```

В macOS/Linux:

```sh
PORT=8766 npm start
```

Параметры по умолчанию находятся в `config/server.json`. Переменные `HOST` и `PORT` имеют приоритет. `HOST=0.0.0.0` открывает прослушивание всех интерфейсов и используется внутри контейнера. По умолчанию запуск вне контейнера доступен только локально.

## Docker

Docker Engine / Docker Desktop с Compose v2:

```sh
docker compose -f config/compose.yaml config
docker compose -f config/compose.yaml up --build -d
docker compose -f config/compose.yaml ps
docker compose -f config/compose.yaml down
```

Откройте `http://127.0.0.1:8765/`. Если порт занят локальным сервером, остановите его перед запуском контейнера. Конфигурация публикует порт только на локальном интерфейсе компьютера. Приложение работает от непривилегированного пользователя, с файловой системой только для чтения. Томов с медицинскими данными нет.

Базовый образ `node:22-alpine` может получать обновления. Для фиксированного окружения вне хакатона следует закрепить проверенный digest образа. На компьютере разработки Docker отсутствует, поэтому фактическая сборка и запуск контейнера проверяются отдельным заданием GitHub Actions. Не считайте наличие файлов подтверждением успешного запуска: результат смотрите в Actions.

## Автономная демонстрация

На компьютере разработчика выполните `npm run build`, скопируйте `release/leya.html` на устройство для защиты. Откройте в браузере и проверьте учебные примеры, импорт, памятку и печать до выступления. На целевом устройстве не нужны Node.js, Docker и интернет.

## Статический хостинг

Размещайте содержимое `dist/` как корень сайта, сохраняя вложенные пути. Для основной страницы используется `index.html`. Серверная обработка и API-ключи не нужны. Используйте HTTPS на выбранном провайдере. Не загружайте на хостинг исходный датасет, бланки и папку аудита обучения.

Опубликованный сайт: https://leya-triplet.netlify.app/. Он размещён в аккаунте команды «Триплет» на Netlify и доступен без регистрации. После изменения кода необходимо повторно загрузить содержимое `dist/` в существующий проект Netlify и проверить публикацию. Адрес и QR-код при таком обновлении сохраняются. Ссылка `127.0.0.1` работает только на компьютере, где запущен локальный сервер.

## Повторное обучение

Оно не требуется для запуска готового сайта. Нужны Python 3.12, доступ к разрешённым исходным данным и отдельное окружение:

```sh
python -m venv .venv
```

Windows PowerShell:

```powershell
.venv/Scripts/python.exe -m pip install -r training/requirements.txt
.venv/Scripts/python.exe training/train.py --data "путь/к/deficiency_anemia.csv" --dictionary "путь/к/variables.xlsx" --audit-dir "audit"
```

macOS/Linux:

```sh
.venv/bin/python -m pip install -r training/requirements.txt
.venv/bin/python training/train.py --data "путь/к/deficiency_anemia.csv" --dictionary "путь/к/variables.xlsx" --audit-dir "audit"
```

Папка `audit` содержит исходные признаки и исключена из публикации. После обучения повторите проверки и сборку. [Методика обучения](MODEL_CARD.md).
